# 공식 공격 범위 표시 높이 통일

2026-11-01

문제는 실제 지형 높이가 아닌 범위 오버레이의 높이 결정 경로였다. 3D 범위 표시는 `_nativeTileHeight()`로 장식과 메시의 표면까지 측정했다. 따라서 같은 종류의 지면에서도 모델 표면에 따라 높이가 달라졌고, 언덕·금지 블록·사격대도 각각 다른 결과가 나올 수 있었다. 2D 공식 줄무늬는 모든 타일에서 높이 0을 사용했다.

수정 후 공식 공격 범위 줄무늬는 다음 두 표시 평면을 사용한다.

- 일반 지면: 0
- 언덕·장애물 및 사격대 타일: 기존 언덕 표시 기준인 `TILE_H.wall`(0.42타일)

기존의 겹침 방지용 작은 오프셋(2D 0.012, 3D 0.004)은 유지한다. 실제 모델이 이 표시 평면보다 높아도 범위가 그 안에 묻히지 않도록, 3D 공격 범위 오버레이에만 깊이 검사를 해제한다. 유닛은 기존처럼 보드 위의 별도 레이어에 그려진다. 배치 가능 표시 등 다른 마크의 원래 표면 높이와 깊이 검사는 유지한다.

지형 분류·실제 `heightAt()`·지형 메시·사격대 모델·오퍼레이터 배치 높이·공격 판정은 변경하지 않았다. 사격대의 실제 높이 0.465, 금지 블록 0.3, 분리 벽 0.55도 그대로다. 범위 표시가 참조하는 전용 함수만 별도로 추가했다.

검증:

- `test/render/range-height.test.js`: 두 표시 높이, 사격대/장애물 분류, 비활성 장치 제외, 실제 지형 불변, 3D 범위 메시 정점, 다른 표시의 기존 높이 유지, 2D/3D 분류 일치를 검사한다.
- 범위·3D 보드·장면 테스트 81개 중 80개 통과, 1개 건너뜀. 정적 import 및 공백 검사 통과.
- 별도로 실행한 기존 `tiles.test.js`의 2개 실패, `board3d-crate.test.js`의 1개 실패는 HEAD 이전 작업본에서도 동일했다. 해당 기대값이나 무관한 코드는 바꾸지 않았다.
- 실제 Chromium의 같은 3D 보드/같은 범위로 변경 전·후를 촬영했다. 수정 전 표시 높이는 0/0.3/0.42, 수정 후는 0/0.42였다(오프셋 제외). 두 화면 모두 3D 렌더러 활성화, 페이지 예외 0을 확인했다.
- 모든 맵·카메라 조합을 실기기에서 확인했다는 의미는 아니다.
