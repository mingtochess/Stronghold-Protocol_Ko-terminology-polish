# 탈룰라 화염의 줄·이동 경계 점검

2026-11-01, 스킬명은 사용자 지정 **작열하는 광환**으로 변경했다.

## 공식 범위와 확인 결과

PRTS 원문은 기본 5줄, 과부하 시 **최대 13줄**로 명시한다. 배치 방향에 수직인 폭이며 맵 밖의 줄은 제외한다. 소환 지점은 원문의 제한대로 자신의 뒤 최대 11칸까지다. 이 제한은 발사 후 전진 거리와 별개다.

적이 없는 4인·8인 연합방어에서 위·아래 방향의 과부하 13줄은 수정 전에도 모두 생성됐다. 따라서 첨부 화면만으로 특정 줄이 아예 생성되지 않았다고 단정하지 않는다. 적에 닿은 불덩이는 해당 줄만 폭발하고 사라지는 것이 정상이며 이 경우도 별도로 시험했다.

## 발견한 문제와 수정

1. **스킬 종료 시 비행 중인 화염 삭제:** 스킬이 끝나면 이미 발사된 화염까지 시뮬레이션과 공식/간소 표시에서 모두 삭제했다. 이제 새 소환만 멈추고 기존 화염은 적 충돌 또는 비행 수명 만료까지 진행한다. 퇴각 후에도 비행이 멈추지 않는다.
2. **연합방어의 이동 거리:** 현재 전장 사각형의 진행 방향 끝 좌표로부터 남은 거리를 계산한다. 4인(21열)·8인(37열)의 먼 끝과 이후 5칸까지 비행 수명을 산정한다. 이미 이동한 뒤쪽 구간을 다시 더하지 않는다.
3. **연속 시전 식별자 충돌:** 시전할 때마다 파동 번호를 0으로 되돌리면 이전 시전의 비행 효과가 다음 시전에 덮어써질 수 있었다. 파동 번호를 유닛 수명 동안 증가시킨다.
4. **세로 방향 높이:** 공식 화염을 지면 높이 0에 고정해 고지대에서 가려질 수 있었다. 공식·간소 모두 현재 타일의 실제 높이 +0.18타일로 표시한다. 피해·충돌은 기존 지상 좌표를 사용한다.
5. **낮은 FPS에서 표시 위치 지연:** 공식 파티클 시계는 프레임당 시간 증가를 제한하므로 긴 프레임에서 실제 전투 시각보다 뒤처질 수 있다. 이동 화염은 이제 서버의 발사 시각과 보간된 현재 전투 시각으로 위치·만료를 계산한다. 파티클 자체의 기존 시간 정책과 다른 이펙트의 동작은 바꾸지 않는다.
6. **간소 모드의 전역 128개 제한:** 여러 탈룰라의 비행 화염이 합쳐져 128개를 넘으면 다른 유닛의 화염도 먼저 지웠다. 제한을 시전자별로 분리해 서로의 비행 효과를 지우지 않게 했다. 현재 두 시전자 208개를 동시에 유지하는 회귀 테스트가 있다.

## 검증

- `test/sim/talulah-wave-fields.test.js`: 4인/8인 × 설원/기존 전장 2종 × 4방향 × 기본/과부하 × 좌/중앙/우 배치의 144조건. 각 조건에서 유효한 모든 줄의 생성, 뒤쪽 11칸 제한, 발사 후 스킬을 종료해도 모든 화염이 먼 전장 끝을 통과하는지 검사한다.
- 추가로 적 충돌 시 해당 줄만 제거, 겹치는 두 시전의 식별자 독립성, 퇴각 후 비행 지속을 검사한다. 이 파일의 147개 테스트가 통과했다.
- 공식/간소의 지형 높이, 느린 파티클 시계와 실제 전투 시계의 분리, 전역 128개 초과 표시도 테스트한다.
- 관련 회귀 테스트 총 302개 통과, 기존 전투 81개 시나리오 결과 동일, 기존 오퍼레이터 데이터 변경 0개.
- 실제 Chromium에서 4인/8인 세로 배치의 공식 화염 13개, 4인/8인 가로 배치의 공식 화염 4개, 8인 가로 배치의 간소 화염 4개를 확인했다. 모두 페이지 예외와 공식 이펙트 dropped가 0이었다.
- 8인 가로 배치에서는 스킬이 4.1초에 끝난 뒤에도 약 19.2초 시점에 화염이 반대편 36열까지 진행함을 화면과 렌더 원점으로 확인했다. 전장 끝 경계를 실제로 넘는지는 144조건의 시뮬레이션 테스트로 별도 검증했다. 코드 테스트와 실제 화면 검증은 구분한다.
- 첨부 화면과 동일한 적·배치·영상 기록은 없으므로 사진의 각 빈 줄이 충돌 때문인지, 높이·시간 지연 때문인지까지 확정한 것은 아니다.
