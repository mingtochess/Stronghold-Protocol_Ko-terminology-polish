# 커스텀 확장 설정 유지와 버튼 위치 검토

로컬에만 적용했습니다. 커밋·푸시 및 운영 배포는 하지 않았습니다.

## 설정 유지

- 대기실에서 방장이 ‘적용’을 성공적으로 완료한 선택을 브라우저 저장소에 기록합니다.
- 다음 혼자/협동 방 생성 요청에 저장된 선택을 포함합니다. 방 생성 시 서버가 곧바로 적용하므로, 기본 설정으로 먼저 생성됐다가 바뀌는 구간이 없습니다.
- 모두 끈 상태도 저장합니다. 취소하거나 서버 적용이 실패한 선택은 저장하지 않습니다.
- 다른 방에 참가할 때는 그 방장의 선택을 따릅니다. 참가한 방의 설정으로 자신의 저장값을 덮어쓰지 않습니다.
- 삭제된 커스텀 전장은 새 방 생성 시 제외합니다. 잘못된 저장 데이터는 빈 선택으로 처리합니다.
- 기존 스킬·스킨 설정의 저장 키와 데이터는 수정하지 않습니다.

## 문제와 평가 기준

처음 버튼을 오른쪽에서 두 줄로 쌓으면서 하단 바의 고정 높이를 유지해 시작 버튼이 잘렸습니다. 고정 높이를 없애 실제 콘텐츠 높이를 확보하도록 수정한 뒤 후보를 비교했습니다.

평가 기준은 준비 인원·시작 버튼과의 분리, 방 설정이라는 의미의 명확성, 버튼 발견과 클릭의 용이성, 참가자 카드 공간 소모, 화면 끝 잘림 및 겹침입니다.

같은 4인 대기실(사람 1명 + AI 3명)에서 1600×900과 1366×768으로 네 후보를 촬영했습니다. 레이아웃 후보는 실제 DOM/CSS로 비교했습니다. 모든 후보는 비교 시점에 버튼 잘림, 준비 인원 침범, 상단 제목 침범이 없었습니다. 단순히 겹침이 없다는 이유만으로 선택하지 않고 정보의 의미와 기존 조작 위치도 비교했습니다.

| 후보 | 장점 | 단점 | 결정 |
|---|---|---|---|
| A. 오른쪽 오퍼레이터 설정 옆, 시작 버튼 위 | 설정 버튼끼리 모임 | 시작 버튼이 아래 줄로 옮겨짐. 하단 바가 가장 높아짐 | 제외 |
| B. 상단 공통 설정 버튼 옆 | 참가자 카드 공간을 가장 많이 확보 | 방 확장 설정과 개인 환경 설정의 의미가 섞임. 버튼이 작아지고 상단 버튼 밀도가 증가 | 제외 |
| C. 참가자 카드 위 독립 설정 행 | 방 설정임을 분리해 표시. 하단 기존 조작 유지 | 버튼 하나 때문에 화면 전체 너비의 새 행을 소비. 난이도 설정과 떨어짐 | 제외 |
| D. 왼쪽 난이도 설정 아래 | 같은 판에 적용할 설정끼리 모임. 준비 인원과 분리되고 시작/오퍼레이터 버튼 기존 가로 배치 유지 | 왼쪽 설정 영역이 두 줄이 됨 | 채택 |

1600×900에서 A의 하단 바는 약 164px, D는 약 141px였습니다. C는 125px 하단 바 외에 약 68px 독립 설정 행을 더 소비합니다. D는 A보다 약 23px, C보다 약 52px 적게 사용하면서 기존 시작 조작 위치를 유지합니다. B는 125px로 가장 작지만 설정의 적용 범위를 혼동하기 쉬워 제외했습니다.

## 최초 채택안

- 최초 검토에서는 커스텀 확장 설정 버튼을 왼쪽 난이도 설정 아래에 배치했습니다. 선택된 확장 개수 표시는 유지합니다.
- 중앙은 준비 인원과 준비 상태만 표시합니다.
- 오른쪽은 기존 오퍼레이터 설정 → 시작/준비 버튼의 가로 배치로 복원합니다.
- 하단 바는 콘텐츠 높이를 확보하고, 대기실 채팅은 실제 하단 바 높이를 측정해 위쪽 여백을 유지합니다. 화면 크기·글꼴 변경 시에도 다시 측정합니다.

## 사용자 제안에 따른 최종 변경

이후 사용자가 제안한 ‘오른쪽 설정 버튼 두 개를 쌓고, 시작 버튼 높이를 두 버튼 전체 높이에 맞추는’ 안을 최종 적용했습니다. 위 후보 A처럼 시작 버튼이 아래 줄로 내려가는 배치와 다릅니다. 설정은 왼쪽 열, 시작은 오른쪽 열이며 양쪽 위·아래 경계가 일치합니다. 난이도와 중앙 준비 인원 영역은 유지됩니다.

1600×900 실제 브라우저 측정: 설정 버튼 두 개의 폭은 각각 226.75px, 전체 높이는 113.328px입니다. 시작 버튼도 높이 113.328px이며 위·아래 경계가 일치합니다. 1366×768에서도 모든 하단 버튼과 채팅의 겹침·잘림 검사를 통과했습니다. 확장 선택 저장과 새 방 복원 기능도 유지됩니다.
